# Run one sector hearing for frontend demonstration

From `/opt/equipoise`, list the installed groups with `./venv/bin/python scripts/drill/group_hearing.py list`. Resolve the requested group by this list. One operator hosts one hearing for all its actionable members. Slots and member counts are different quantities.

1. Run the dispatch skill's IBKR probe. After it succeeds, run `EQUIPOISE_IBKR_PORT=4001 ./venv/bin/python scripts/drill/group_hearing.py open GROUP_US_CHIPS` (substitute the listed group key). This prepares the constituents together, freezes quotes, news and each member's ruler, and prints the session directory. Keep that directory for resumption. A preparation error stops the hearing.
2. The operator acts as arbiter. Start two independent Codex debaters with the Zealot and Reaper role guides, the debater guide, and only this session's frozen opening materials. For this short demonstration run two rounds. Both file R1 independently; in R2 give each the opponent's archived R1. Seek evidence within the freeze. Never show a later round or a ruling before it is filed. Shared facts are cited once, every member gets its own thesis, opposing evidence and scenario. Keep all filings in English.
3. Save each original filing in the session directory as `R1-Z.json`, `R1-R.json`, `R2-Z.json`, `R2-R.json`. Each has a string `shared` and a `members` object keyed by the exact opening roster. Each member has `thesis`, `reservation`, a schema-3.4 `scenario` with the frozen P0 and T_days, and `execution` using the normal side contract (an empty object is a valid filing). In R2 answer the opponent directly. Focus on price paths, evidence and execution as in the role guides.
4. Write `verdict.json` with `summary`, actual `signatures` (zealot, reaper, arbiter), and `members` keyed by symbol, each containing numeric `weight_z` in [0,1] and a member-specific `reason`. Resolve the exchange for each company. Use the opening prices and issuer-specific evidence to explain the relative weight.
5. Run `./venv/bin/python scripts/drill/group_hearing.py close SESSION_DIRECTORY`. It checks the roster, opening prices, horizons and final scenarios, derives scores and both cards with the frozen ruler, verifies each mixture and recomputation, then emits `frontend/group.json` and one projected detail JSON per member. Give the frontend AI that directory. Confirm the same debate_ref and history across the views, and one matching symbol, reference price and pair of cards per view.

This operator-led demo exports English JSON to the session directory. Production automatic dispatch, PG publication and translation have their own release path. Keep demonstration results out of the production history. For an ordinary independent batch or regional GENERAL see the parent skill.
