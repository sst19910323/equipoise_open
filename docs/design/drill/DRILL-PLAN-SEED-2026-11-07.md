# 演习计划(Drill)入口稿 — 2026-11-07(库主立项, 新 session 从这里起)

## 目的(库主原话大意)

d+20 还是一般, 10 月阴跌 AI 没喊出来。找一些**已知结果的节点**(最好什么样的都有), 用冻结材料让 Claude / Codex(Gemini 呼叫得到就加, 呼叫不到就算)
各自模拟辩论两方, 看在那份材料下怎么做到**利益最大化**, 从而看到: 哪个 skill / 手册用得最多、哪个有漏洞、哪几个本质是一回事重复了。
这是"又薄又坚固"的减法输入, 与增量场(省额度)是两个层面的事; 演习为主, 紧迫性更高。

## 我(Claude)建议的骨架(讨论稿, 库主未逐条拍板)

- **节点集** 8–12 个、类型齐全、结果已知: 阴跌起点(10-06 GENERAL / QQQ)、暴跌后 V 反(10-30、11-05)、财报跳空(NVDA 一场)、假突破、9 月震荡、三镜头分化(DIA 强 QQQ 弱); 美欧日韩至少各一。
- **冻结材料包**两包: A = 当场实际备餐 + 当时 Scout 结果(PG `evidence` 有原文); B = A + 当时已公开但没取到的(慢压力页回填)。晚于 as_of 的一个字不进。
- **断网**: 辩论子代理只许读包, 不许联网(否则知道结果的模型会作弊); 每家先答一道"事后知识检测"(问它 as_of 之后发生了什么), 记录模型版本。
- **度量**每场: 手册调用分布、外呼主题、claims 引用了哪条原则、终报对已知结果按 R25 打分, 与真场并排。"利益最大化" = 同一包下怎么打分最高 →
  反推 没被用的规则(漏洞)/ 总是一起出现的规则(重复)/ 从不触发的规则(可删)。
- **产出**: 规则包用量热图 + 漏洞清单 + 合并候选 + 每个节点一份"当时客观答复应该是什么"的评判稿。
- **顺序**: 可知性审计表(只读, 1–2 天; 副产品 = 节点清单 + 冻结包)→ 演习 → 增量场 full/full 对照在值班空档穿插。

## 补(库主 11-07 深夜): 两层模型同包对打——天花板 vs 真正干活的那个

- **同一份冻结包, 两套辩手各打一场**: ① 最好的模型(Opus 5.5 / Fable 一类)= 天花板, 看这份语料 + 这份材料**最多能打到哪**; ② **生产模型 gpt-6.1-sol**(服务器 codex 身份实际在用的那个)= 现实,
  看它拿同一份语料**实际打到哪**。评判 session 对两场并排判。
- **分工(库主原话)**: 最好的模型那一场是**发现和矫正 skill 的**(找语料的漏洞、重复、理想打法, 提出改法); sol 那一场是**看 skill 行不行的**(改完之后生产模型能不能用好 = 验收)。
  所以是一个循环: 天花板场发现 → 改语料 → sol 场验收 → 不过再改。**目的不是让最好的模型分高, 是把 skill 改到 sol 真能用好**。两场之差拆三类: (a) 语料本身缺(天花板也没打到 → 改规则 / 加数据); (b) 语料在、sol 用不动(天花板打到了、sol 没用上 →
  改措辞 / 拆步骤 / 把判断变成可执行操作, 这是演习的主产出); (c) 材料缺(两家都卡在同一个没有的数 → 数据层)。
- 工程注意: 本机 council CLI 下 `gpt-6.1-sol` 报 400 不可用, 只有服务器 codex 身份能跑 sol → sol 那一场必须在服务器起(断网要在服务器侧落实: `-s read-only` + 只读包);
  Opus 5.5 那一场走 CC 子代理(去掉 WebSearch / WebFetch)。两场都记模型版本与事后知识检测结果。
- 度量加一列: 每条规则 / 手册在"天花板用了 / sol 用了 / 都没用 / 只有 sol 乱用"四格里的落点——sol 乱用的那些就是要改措辞的首批。
